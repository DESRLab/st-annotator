# ⭐ CLI Reference

The command-line interface (`sta`) automatically becomes available once you [install the ST Annotator package](../install.md).

Each subcommand requires you to specify a configuration file. This refers to the [JSON configuration file for ST Annotator](../user/config.md).

## Usage

```
sta <subcommand> -c <config> [options]
```

The built-in subcommands are:

- `init` creates the remote database for the platform.
- `serve` hosts the platform on a server.
- `plugins` lists the plugins available through the configuration file and gives access to their CLIs.
- `bench` runs the version-control benchmarks of the platform, measuring the cost of committing label operations.

## Initialize ST Annotator

Create the remote database for the ST Annotator platform:

```
sta init -c <config>
```

### Options

- `--drop-if-exists` is required to explicitly recreate an existing database.

## Serve ST Annotator

Host the ST Annotator platform on a server:

```
# Serve over HTTP
sta serve -c <config> --http <host>:<port>

# Serve over HTTPS
sta serve -c <config> --https <host>:<port>,<cert>,<key>
```

The `sta` command is installed into whichever Python environment holds the
backend package. Inside a checkout that is the workspace virtual environment, so
either activate it first or prefix any command here with `uv run --package sta`
(which is what the repository's scripts do).

### Options

- `--http` and `--https` are mutually exclusive and one of them is required; a
  call that omits both or gives both is rejected as a usage error.
- `--frontend-url` sets the browser origin allowed by CORS. It defaults to
  `STA_FRONTEND_URL`, then `http://localhost:5173`. Both the flag and the
  environment variable accept a single origin and are rejected when given a
  comma-separated list.
- `--jwt-private-key` names the PEM file whose EC (P-256) key signs access and
  refresh tokens with `ES256`. It takes precedence over
  `STA_JWT_PRIVATE_KEY_PATH`; with neither, `--testing` generates an ephemeral
  keypair that dies with the process. Create a key with
  `openssl ecparam -name prime256v1 -genkey -noout -out <jwt_path>`.
- `--debug` enables backend debug logging. It does not disable production
  signing-key or trusted-proxy checks.
- `--testing` is development only: it drops and recreates the separate
  `<db>_test` database, with a default `admin`/`admin` root user.
- `--limit-concurrency` bounds concurrent connections/tasks and
  `--timeout-keep-alive` controls idle keep-alive duration. For multiple worker
  processes, run `sta serve` under a process manager or container orchestrator.
- Outside `--testing`, the server refuses to start unless a readable P-256
  signing key is configured through `--jwt-private-key` or
  `STA_JWT_PRIVATE_KEY_PATH`, and warns on stderr when `STA_TRUSTED_PROXY_IPS`
  is unset. See
  [Hosting the ST Annotator Platform](../user/host.md) for both.

### Examples

Host the platform on `http://localhost:5014`:

```
sta serve -c <config> --http :5014
```

Host the platform on `https://192.0.0.1:5014` with HTTPS certificate `foobar.crt` generated from private key `foobar.key`:

```
sta serve -c <config> --https 192.0.0.1:5014,foobar.crt,foobar.key
```

Host the platform outside `--testing`, which requires a stable signing key generated by `openssl ecparam -name prime256v1 -genkey -noout -out <jwt_path>`:

```
sta serve -c <config> --http :8000 --jwt-private-key <jwt_path>
```

## Plugin CLIs

List the plugins available through a configuration file:

```
sta plugins -c <config>
```

Access the CLI of a plugin as a subcommand:

```
sta plugins -c <config> <plugin>
```

## Benchmarks

Measure the cost of persisting label operations to the remote database:

```
sta bench label-queries -c <config> -o <output-prefix> [options]
```

Both `-c` and `-o` are required; `-o` prefixes the JSON files written by the run. The sampling options (`--plugin`, `--user-count`, `--commit-count`, `--branching-prob`, `--label-entity-prob`, `--label-create-prob`, `--label-delete-prob`, `--init-label-count`, `--seed`) and the reporting options (`--query-plan`, `--log-storage`, `--no-overwrite`) are listed by `sta bench label-queries --help`.

The repository's benchmark sweeps are driven by shell scripts that call this command:

- `scripts/perf_label_latency.sh` — single-user latency across delete-probability settings.
- `scripts/perf_label_latency_multi_user.sh` — the same sweep for several concurrent users.
- `scripts/perf_label_storage.sh` — storage cost with delta encoding enabled and disabled, via `STA_USE_DELTA_ENCODING`.

Each script writes into its own `OUTPUT_DIR` and passes `--no-overwrite`, so an interrupted sweep can be re-run to fill in the combinations it has not completed yet. Start from these scripts when constructing a new benchmark run.
