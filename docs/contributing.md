# ⭐ Contributing Guide

Thank you for spending your time and energy on this project! Here is how you can contribute to ST Annotator.

## Types of Contributions

### Questions

Our documentation only goes so far towards explaining the ST Annotator platform. If you still have questions, feel free to [open a new issue](https://github.com/DESRLab/st-annotator/issues/new). We will try to answer them as soon as possible.

Every question counts! Based on your questions, we can update the documentation to be more clear and comprehensive.

### Bug Reports

If you suspect a bug or encounter unexpected behaviour, please [open a new issue](https://github.com/DESRLab/st-annotator/issues/new). We will try to answer them as soon as possible.

We can only dedicate so much time towards bug fixes. If you wish to have the bug fixed sooner, consider [implementing the fix](#making-changes) yourself. For non-UI bugs, please include regression tests to verify the fix and avoid future occurrences. It should not take long for us to review bug fixes.

### Feature Requests

You can request a new feature by [opening a new issue](https://github.com/DESRLab/st-annotator/issues/new). Depending on the feature, expect this to take considerably longer to process than other types of contributions.

You may choose to [implement the new feature](#making-changes) yourself. To speed up the review process, we recommend that you include some test cases to demonstrate the new feature.

## Making Changes

First, create a fork of our repository and clone it to your machine. Then, [install the repository](./install.md) and [configure the environment](./user/config.md).

Be sure to check out our [developer guide](./dev/index.md) and [API reference](./api/index.md) to get familiar with our code.

Once you have committed your changes, you can create a pull request as detailed [here](#submitting-a-pull-request) to merge it into our repository.

## Submitting a Pull Request

You can open a pull request against our repository on [GitHub](https://github.com/DESRLab/st-annotator/pulls). Before submitting, please make sure that your changes satisfy [our coding conventions](./dev/conventions.md).

Once we review and approve the pull request, expect it to be included in the next release. We will acknowledge your efforts by mentioning you in the release notes.
